Ch 2 • Mutability vs Immutability
What happens in computer memory when you append to a Python list versus concatenating a string?
Think about pointer arrays versus object re-allocation and memory IDs.
Click card to rotate & reveal answer
Answer & Key Takeaway

Lists are mutable: appending modifies the array in-place without changing the list's memory address (id(list) remains identical). Strings are immutable: string concatenation creates a brand-new string object elsewhere in memory and updates the reference.

id(a) == id(a.append(4)) # True for lists

Python 3: From Scratch to Production — Course Notes

Chapter 01: Installation, Virtualenv & Tooling

Always create isolated virtual environments per project to prevent polluting global pip packages. Never install third-party packages into the global system interpreter:

  • 04:15 Run python -m venv .venv in the repository root.
  • 08:50 Activate via source .venv/bin/activate on Unix or .venv\Scripts\activate on Windows.

Chapter 02: Data Types, Strings & Mutability

Understanding variable identity and memory addresses is foundational to preventing subtle bugs with default parameters:

  • 12:30 Never use mutable objects (like [] or {}) as default parameter values. Python evaluates defaults once at function definition time.
  • 16:50 Use None as the default sentinel and initialize a new list inside the function body.

Chapter 03: Conditionals, Loops & Iterables

Python loops operate on iterator protocols rather than simple index counting:

  • 06:50 Prefer enumerate(iterable, start=1) over manual index incrementation.
  • 14:50 The else clause on a for loop executes only if the loop completes without hitting a break statement.

Chapter 04: Functions, Closures & Decorators

Decorators wrap functions using higher-order closures to augment behavior without modifying source code:

  • 10:12 Always import from functools import wraps and decorate the wrapper with @wraps(func) to preserve docstrings and __name__.
  • 12:45 Practical pattern: execution timing with time.perf_counter().
